# Organization Security Policy

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability. Use the repository's private security advisory feature or the security contact documented by that repository. Include the affected repository and version, impact, reproduction steps, and any proof of concept needed to validate the report. Do not include personal data or secrets that are not necessary for triage.

Researchers should make a good-faith effort to avoid accessing, modifying, deleting, or exfiltrating data; degrading availability; or using a vulnerability beyond what is necessary to demonstrate it.

## Response

Maintainers will acknowledge reports, assess impact and affected versions, coordinate remediation, and communicate disclosure timing where possible. Response targets and supported versions may be defined by each repository.

## Repository-specific scope

Each repository must retain a local security supplement when it has application-specific assets, hosted services, deployment ownership, supported-version rules, or reporting contacts that are not covered here. The local supplement must link back to this organization policy.
